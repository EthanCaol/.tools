# 语音输入(Qwen3-ASR 版)

按住右 Ctrl 说话,松手后本地 Qwen3-ASR 模型转写,文字逐字插入当前光标位置。

全程离线,音频和文本不离开本机。这是 `whisper-typing` 的替代版本,把引擎从
faster-whisper 换成了 Qwen3-ASR。

## 组成

根目录只有 3 个入口文件:

| 文件                | 作用                                       |
| ------------------- | ------------------------------------------ |
| `启动.bat`          | 启动。转给 `tools\静默启动.vbs`,不弹窗口   |
| `开机自启-开启.bat` | 在 Startup 文件夹建快捷方式,登录时自动启动 |
| `开机自启-关闭.bat` | 删除该快捷方式                             |

| 其余文件             | 作用                                                           |
| -------------------- | -------------------------------------------------------------- |
| `server.py`          | 常驻服务。加载 Qwen3-ASR、控制麦克风录音、执行转写             |
| `dictate.ahk`        | AutoHotkey v2 脚本。注册热键、提供托盘菜单、把识别结果逐字输入 |
| `config.ini`         | 全部可调参数                                                   |
| `tools\静默启动.vbs` | 真正的启动逻辑。隐藏启动服务,等就绪后拉起听写脚本;启动失败会弹窗 |
| `tools\等待就绪.py`  | 轮询服务直到就绪                                               |
| `tools\停止全部.py`  | 结束服务与听写脚本;托盘菜单的「退出」也用它                    |
| `tools\生成预热语音.py` | 生成静态 cache 预热用的语音。文件缺失时服务会自动调用        |
| `logs/`              | 运行日志。`server.log` 记服务、`ahk.log` 记听写脚本、`transcripts.log` 记每次识别的全文     |

**编码约定**:所有文本文件都是 UTF-8。`.bat`、`.vbs`、`.ahk` 带 BOM —— `cmd`
和 `wscript` 没有 BOM 时会按系统代码页解析文件,而本机代码页是 65001(UTF-8),
存成 GBK 会显示乱码。

## 为什么用 Qwen3-ASR 而不是 Whisper

在本人录音上做的同条件对比(同一段 30 秒中文、同一段 35 秒带口音英文):

|                  | Qwen3-ASR 1.7B     | Whisper large-v3-turbo      | X-ASR zh-en | Belle-zh          |
| ---------------- | ------------------ | --------------------------- | ----------- | ----------------- |
| 中文检查点       | 7/9                | 3/9                         | 7/9         | 5/9               |
| 英文术语(带口音) | 最好               | 中                          | 差          | 差                |
| 静音幻觉         | **无**             | **有**(吐 YouTube 字幕水印) | 无          | 无                |
| 热词             | **支持且实测有效** | 仅 initial_prompt           | 不支持      | 仅 initial_prompt |
| 35 秒音频耗时    | 2.4s               | **0.81s**                   | 1.05s       | 2.72s             |

关键差异:

- **静音幻觉**。Whisper 在无语音输入时会复述训练数据里高频出现的 YouTube 字幕
  水印(实测输出 `优优独播剧场——YoYo Television Series`)。Qwen3-ASR 输出空字符串。
- **英文术语**。带口音说 `accuracy`、`baseline`、`throughput` 时,Whisper 和
  X-ASR 会按音拼词(如 `their currency`、`best line`),Qwen3-ASR 正确。
- **热词**。在 `config.ini` 的 `prompt` 里列出专名,能修正人名一类的错误
  (实测把「陈晨」放进词表后,`晨晨` 变成 `陈晨`)。

刚换过来时比 Whisper 慢约 3 倍,用静态 KV cache(见「配置」一节)把差距补回之后
两者已经相当:同一段 35 秒样本,Qwen 0.74 秒,Whisper 0.81 秒。

### 耗时实测

| 你说多久 | 转写耗时 |
| -------- | -------- |
| 1 秒     | 0.31s    |
| 3 秒     | 0.64s    |
| 30 秒    | 0.87s    |
| 35 秒    | 0.74s    |

数字取自 `logs\server.log` 的实际使用记录。1 秒和 3 秒那两行能看出约 0.3 秒的固定
开销,与音频长短关系不大;长音频摊下来约 **9.8 毫秒/输出 token**。

0.6B 和 1.7B **完全一样快** —— 瓶颈是生成循环的每步固定开销,不是模型运算量。
因此换小模型或做量化都不会更快。

## 日常使用

在任意输入框里按住**右 Ctrl** 说话,提示条显示「录音中」;松开后变为「转写中」,
识别完成的文字自动插入光标处。

### 启动与退出

| 操作                       | 方法                                              |
| -------------------------- | ------------------------------------------------- |
| 启动                       | 双击 `启动.bat`,或 `tools\静默启动.vbs`(两者等价) |
| 退出                       | 右键点击右下角托盘图标,选「退出(并停止服务)」     |
| 开启开机自启               | 双击 `开机自启-开启.bat`                          |
| 关闭开机自启               | 双击 `开机自启-关闭.bat`                          |
| 托盘图标不见了、服务还在跑 | 运行 `.venv\Scripts\python.exe tools\停止全部.py` |

启动**全程不显示窗口**,服务要加载模型并预热约 24 秒。期间屏幕上什么都没有,
就绪之后右下角会弹一条「语音输入已就绪」—— **看到这条提示才说明可以用了**。
启动失败会弹窗提示,原因写在 `logs\server.log`。

`启动.bat` 里只有三行转发。双击 `.bat` 时 Windows 必然先开一个控制台窗口,这一点
从 bat 内部消除不掉,所以真正的逻辑都放在 `tools\静默启动.vbs`(开机自启指向的
也是它),避免同一套启动流程有两份实现。

服务已经在跑时重复启动是安全的:`静默启动.vbs` 会先探一下,已就绪就直接跳过,
不会把服务重启一遍。

## 与 whisper-typing 的冲突

两个版本不能同时运行,有三处冲突:

| 冲突         | 说明                                                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| **热键**     | 两边都注册右 Ctrl,同一时刻只能跑一套                                                                                      |
| **开机自启** | 本项目的快捷方式是 `语音输入-Qwen.lnk`,旧项目是 `语音输入.lnk`,两个都在 Startup 里会同时启动并抢热键                      |
| **进程清理** | 旧项目的 `tools\停止全部.py` 按文件名 `dictate.ahk` 匹配,**会把本项目的听写脚本一起杀掉**(本项目那份已改成按完整路径匹配) |

切换到本项目的完整步骤:

1. 旧项目托盘右键「退出(并停止服务)」
2. 旧项目里双击 `开机自启-关闭.bat`
3. 本项目里双击 `开机自启-开启.bat`
4. 本项目里双击 `启动.bat`

## 配置

改 `config.ini` 后需要重启 `启动.bat`。

### 模型

```ini
[model]
name=Qwen/Qwen3-ASR-1.7B-hf
device=auto
prompt=
max_new_tokens=256
```

- `name`:本机已下载 `Qwen/Qwen3-ASR-1.7B-hf` 和 `Qwen/Qwen3-ASR-0.6B-hf` 两个,
  改这一行即可切换。**1.7B 和 0.6B 速度一样**,1.7B 更准,没有理由用 0.6B。
- `device`:`auto` 有 GPU 就用 GPU。GPU 上用 bf16,CPU 上自动降为 float32。
- `prompt`:热词/上下文,留空表示不用。内容是一段自由文本,建议把常说的专名和
  英文术语都列进去。
- `max_new_tokens`:单次生成上限,256 够很长的句子了。

### 静态 KV cache

```ini
[model]
static_cache=true
```

开启后生成从 28.7ms/token 降到 **9.8ms/token**。原理:默认的 KV cache 每步都在
变长,张量形状每次都不同,CUDA graph 用不上,只能一个个启动内核;静态 cache 预分配
固定长度,形状固定,于是能走编译路径。代价是启动时多约 16 秒,总启动时间从 8 秒
变成约 24 秒,只在开机那一次感受到。

预热依赖三样东西,缺任何一样都会**静默**退化成默认模式:

- **`triton-windows` 包** —— Windows 没有官方 Triton
- **两个不同长度的预热** —— PyTorch 在前两个形状各编译一次之后才会切到动态形状,
  只预热一次的话,第一个真实请求要现场编译,卡 20 多秒
- **真实语音** —— 静音、白噪、门控噪声、交替方波、扫频都试过,这些合成信号只产出
  4 个 token 且文本为空,解码循环没走完,编译根本不触发

预热语音由 `tools\生成预热语音.py` 生成:用 Windows 自带的语音合成说一段话,输出
`tools\预热.wav`(16 kHz 单声道 16 bit,16 秒)。文件不存在时服务会自动调用它,
仓库里因此不需要存音频 —— 生成脚本是纯文本,合成的也不是录制者的声音,可以正常提交。

同样的时长下,**合成语音比带停顿的录音生成的 token 多**,编译时间也就长一些
(约 16 秒对约 14 秒),总启动时间相应从约 21 秒变成约 24 秒。

预热完成后会再拿一个没预热过的长度验证;超过 3 秒就判定没生效并回退默认模式。
这道检查是必需的 —— 失败模式不报错,只表现为「每条都慢 3 倍」。

### 录音设备

```ini
[capture]
device=
```

留空表示跟随系统默认输入设备。列出设备:

```
.venv\Scripts\python.exe -c "import sounddevice as sd; [print(i, d['name']) for i, d in enumerate(sd.query_devices()) if d['max_input_channels']>0]"
```

### 静音裁剪

```ini
[capture]
trim_silence=true
trim_threshold_dbfs=-45
trim_margin_ms=300
```

Whisper 版靠它内置的 Silero VAD 去除静音,这里用能量门限代替:按 30ms 分帧算
均方根,低于门限的算静音,裁掉首尾并各留 `trim_margin_ms` 的余量。

**Qwen3-ASR 对静音输出空字符串,不裁剪也不会出错**,裁剪只为了少喂音频、省一点
算力。如果发现字头字尾被切掉,调大 `trim_margin_ms` 或把 `trim_silence` 设为 `false`。

### 听写记录

```ini
[log]
save_text=true
```

开启后,每次识别的**全文**会追加到 `logs\transcripts.log`,一行一条,制表符分隔:

```
2026-10-14 19:19:03	0.73	0.45	测一下,测一下。
```

四个字段依次是时间、音频时长、转写耗时、文本。用制表符而不是逗号 —— 识别文本里
本来就有逗号;文本里若出现制表符或换行会被替换成空格,保证一条记录只占一行。

用途是积累几周后统计词频,挑出常说的专名和英文术语填进 `[model]` 的 `prompt`,
这样热词表按实际说话内容定,不靠回忆。写入开销实测 0.15 毫秒一次,可忽略。

**注意这是把你说过的每一句话都落盘**,其中可能有密码一类的私人内容。文件只在本机
`logs\` 下,`.gitignore` 已排除 `logs/`,不会进版本库。不想记就把 `save_text` 改成
`false`,或者直接删掉这个文件。

只能从文本里看出「你常说什么」,**识别错的词不会自动标出来**。热词表主要靠前者
已经够用;要抓错误得自己发现时记一笔。

## 排查

**双击启动后没反应**
启动是静默的,屏幕上看不到进度。先等足约 24 秒(加载模型 + 静态 cache 编译预热),
再看右下角有没有「语音输入已就绪」。若一直没有,说明启动失败,看
`logs\server.log` 末尾的报错;失败时 `静默启动.vbs` 应该也弹了窗。

**识别出的字进不了某些窗口**
以管理员身份运行的程序会拒绝普通进程的模拟键盘输入。此时用管理员身份运行
`启动.bat`。

**没有插入任何文字**
录音短于 `min_duration_ms`(默认 300 毫秒)会被丢弃;裁剪后有效语音不足
300 毫秒也会被丢弃。两种都会在 `logs\server.log` 里留下记录。

**显存占用**
Qwen3-ASR 1.7B 以 bf16 常驻,实测约 5.8 GB 显存,比 Whisper turbo 的 1.6GB 高不少。
要腾出显存,把 `device` 改成 `cpu`(会慢很多),或改用 0.6B。
